# 2026-11-07 工作日志

## 视频极速压缩：取消 4GB 大小上限并调整相关文案（版本 1.12.1）

对应提交：「视频极速压缩：取消 4GB 大小上限并调整相关文案」

### 一、改动内容（逐条对应 commit message）

1. **取消 4GB 硬上限**：`compress-fast/page.tsx` 的 `MAX_FILE_SIZE` 改为
   `SLOW_WARN_FILE_SIZE`（仅作提示阈值），`FileDropZone` 的 `maxSize` 从 4GB 改为
   `Number.POSITIVE_INFINITY`，拖拽区不再按大小拒绝文件
   - 依据：`fastCompress.ts` 用 mp4box 跳读 moov + `File.slice` 按样本随机读，
     **文件大小本身不是门槛**，没有把整份载入内存的一环
   - 4GB 只是当初保守设的数字，不是浏览器/算法限制
2. **超过 4GB 改为软提示**：琥珀色文案按用户给的原文逐字写入
   `文件 X GB：文件较大，处理时间较长，请耐心等待。建议使用Chrome/Edge浏览器，处理期间请勿关闭或刷新页面。`
   （`X GB` 动态取 `formatFileSize(file.size)`）；保留原有 >500MB 提示，两者互斥显示
3. **修掉 `InfinityMB` 显示**：`maxSize={Infinity}` 时 `FileDropZone` 默认副标题会算出
   `单文件最大 InfinityMB`，故必须传 `maxSizeLabel` 覆盖
4. **五处对外文案去 4GB 化**（均经用户逐条过目确认）：
   - 页面描述 → `基于 WebCodecs 硬件加速的极速压缩，支持 MP4(H.264) 视频，所有处理在浏览器本地完成`
   - 拖拽区主标题 → `拖拽 MP4 视频到此处，或点击选择`
   - 拖拽区副标题 → `文件越大处理越慢`（页面显示「支持拖拽上传，文件越大处理越慢」）
   - `tools.ts` 工具描述 → `基于 WebCodecs 硬件加速的极速压缩，支持 MP4(H.264) 视频，本地转换不上传`
   - `compress/page.tsx` 引导句 → `（硬件加速，但仅支持 MP4/H.264 输入与 MP4 输出）`
5. **版本号** `1.12.0 → 1.12.1`，changelog 顶部新增 1.12.1 条目（2 条 changes）

### 二、用户明确的文案偏好（以后照做）

- **不要在描述里强调「不设上限 / 不限大小」**——用户原话「其他描述里不需要强调『视频不设上限』」。
  把过时的限制字样删掉即可，不要换成另一种承诺式表述
- 慢速提示要**简短、口语、给行动指引**，不要解释技术因果。我第一版写了
  「解码与编码按帧进行，耗时与文件体积近似成正比…不要休眠」，被要求改掉：
  既啰嗦，因果也不严谨（耗时取决于时长与帧数，不是文件体积）
