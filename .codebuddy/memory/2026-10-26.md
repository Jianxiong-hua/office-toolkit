### 一、A 方案核心：WORKERFS 挂载（解决大文件）

- 起因：1GB 级的非 MP4 视频（MKV/AVI 等），四个视频工具全都处理不了
  （ffmpeg 路径限 200MB，WebCodecs 只认 MP4/MOV + H.264）
- `@ffmpeg/core` 与 `core-mt` 都编译了 WORKERFS（js 里各 21 处引用，静态确认）
- `runConversion` 新增 `inputFile?: File`：>200MB 时 `mount(FFFSType.WORKERFS, { files }, "/mnt")`，
  args 里输入路径替换成 `/mnt/<name>`，`finally` 里 `unmount` + `deleteDir`
- **必须用 `new File([file], "input.<ext>")` 包装**：挂载后路径由 `File.name` 决定，
  包装只新建元数据、不复制内容，这样路径才能与 args 里写的一致
- 上限：视频压缩 2GB、GIF 兼容模式 2GB；极速模式维持 4GB

### 二、core-mt 全面停用（重要，三次实测）

多线程 core 在本环境的**解码阶段必然卡死**，探测索引阶段却正常：

| 场景 | 单线程 | 多线程 |
| --- | --- | --- |
| GIF 750 帧 | 155.7 秒完成 | 295 秒仍停第一阶段 |
| WORKERFS 解码 1 秒 | 353 ms | 无响应 |
| MP4 压缩 50 秒片段 | 63.6 秒 | 66 秒仍 0% |

- 结论：`compress.ts`、`gif.ts`、挂载路径全部 `forceSingleThread: true`
- 教训：只读索引（`-i`）能通过 ≠ 能解码；必须真正解一段码才能暴露线程问题
- `public/_headers`（COOP/COEP）保留但当前无用途
- 顺带修掉「压缩页先按多线程加载、runConversion 又要求单线程」导致的重载浪费，
  页面统一 `ensureLoaded({ multiThread: false })`

### 三、视频压缩正确性修复（用户实测驱动）

1. **体积反而变大**：106.3MB / 281.6s ≈ 3.0Mbps 的片源，用 crf23 + ultrafast 重编成 10.3Mbps，
   50 秒输出 64.2MB。修复：加 `-maxrate`/`-bufsize`（源码率 × 档位比例，
   沿用 fastCompress 的 0.85/0.6/0.4）。修复后 50 秒 → 12MB
2. **默认 preset 不可用**：`fast` 在 1080p 上 50 秒需约 75 分钟（wasm 无汇编，
   日志 `[libx264] using cpu capabilities: none!`），改默认 `ultrafast`（约 65 秒）
3. **`-t` 位置错误（内容 bug）**：`-t` 跟在 `-i` 后是「输出时长」，而 `setpts=PTS/speed`
   会压缩时间轴 → 截取范围被放大 speed 倍（选 4 秒 + 2x 实际读 8 秒）。改到 `-i` 之前
4. **进度百分比错误（三层原因）**：
   - 第一层：`-progress pipe:1` 的 stdout 不经日志回调（实测 0 次命中），作废
   - 第二层：ffmpeg 自估分母在变速下不准 → 改用自己的分母
   - **第三层（真因）：`ProgressEvent.time` 单位是微秒**，我一直当秒用 → `time/分母`
     永远爆表，1 秒即到 99%。改成 `time / 1e6 / expected` 后正常
   - 分母取「输出时长 = 片段时长 / 倍速」（`out_time` 是输出时间轴）
   - 进度封顶 0.99，`exec` 返回后才 100%
5. **收尾慢**：去掉 `-movflags +faststart`（编码完成后重写整个文件，只为网站边下边播服务）
6. **体积对比口径**：截取/倍速时不再与完整文件比较，改按「同长度」
   （`segmentRatio = 片段时长 / 倍速 / 总时长`）。用户明确选这个严谨口径，
   即使省幅从 67% 降到 34%
7. **3 倍速**：视频压缩页补上 3x（GIF 页上一轮已加）
8. 压缩页增加「已用 N 秒」秒表 + ffmpeg stderr 前 20 条采样日志（`debugLog`）

### 五、环境踩坑

- `npm run build` 会在删除 `.next`/`out` 时触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，
  需先 `Remove-Item -Recurse -Force .next,out`（PowerShell 原生删除不受 node 链钩子影响）
- PowerShell `git log --pretty="%h %ad"` 里的 `%` 会被 cmd 吞掉，改用 `git log -1`
