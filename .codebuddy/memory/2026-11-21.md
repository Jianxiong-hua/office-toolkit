### 二、关键结论与技术要点

- **`out` 静态导出不能双击 `index.html` 打开**：资源是 `/ _next/...` 绝对路径（file:// 下解析到盘符根），且 Next 客户端路由靠 `fetch('*.txt')` 拉 RSC payload、PDF.js/ffmpeg 的 Worker 在 file:// 下被浏览器拦。改相对路径也救不了，只能走本地 HTTP 服务
- **选 static-web-server 2.44.3 而非 Caddy**：单 exe 6.9MB（Caddy 约 45MB），`[[advanced.headers]]` 可配 COOP/COEP，实测根路径与深层路由都能带上
- **`sws.toml` 关键配置**：只绑 `127.0.0.1`、端口 8788、`directory-listing = false`、`page404 = "404.html"`、COOP same-origin + COEP require-corp
- **`python -m http.server` / `npx serve` 都不会发 COOP/COEP**（那是 Cloudflare/Netlify 读 `_headers` 的行为），本地预览视频工具会自动降级单线程，这是正常现象不是 bug
- **构建产物被误发的真实事故**：`out/` 停留在 2026-10-27，源码已到 2026-11-07，前后两轮交付的包都是过期内容。脚本里加的「源码比产物新就警告」检查抓到了它，此后 post-commit 一律 `-Build`
- **PowerShell 5.1 按 GBK 读 UTF-8 无 BOM 的 .ps1**：中文注释全乱并导致解析失败。脚本必须存为 **UTF-8 with BOM**；`replace_in_file` 编辑后要复查 BOM 是否还在（实测多次编辑后 BOM 保留）
- **打包前必须结束残留的 `static-web-server.exe`**：它锁住包里的 exe，`Remove-Item` 报 Access denied。脚本里用 `Get-CimInstance Win32_Process -Filter "Name = 'static-web-server.exe'"` 检测并结束
- **`Get-Process static-web-server` 查不到该进程**（实测），要用 CIM 查询
