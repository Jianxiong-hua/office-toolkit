### 踩坑记录（普适规则）

1. **Hirschberg 分割点求和公式**：lcsRowBackward 返回的是「右半 a 与 b 第 j 行到末尾」的 LCS，
   分割目标和是 l1[j] + l2[j]（j 为 b 的相对偏移），写成 l2[n-j] 会让相同文档被切成大量 changed。
   手算小样例（3 行相同文档）定位，断言红灯直接暴露。
2. **execute_command 参数里的反斜杠序列会变形**（如正则 /\r\n|\r|\n/ 写入源码后变成双反斜杠字面），
   TS 源码中的转义序列一律用 String.fromCharCode 拼接规避（CR=13, LF=10）。
3. **断言脚本自身也会错**：构造多行文本用 join("") 会把空行元素拼没（空行之间没有分隔符），
   应把行数组用 join(LF) 连接。测试失败先怀疑测试再怀疑实现。
4. **predev 的 rmSync 会被 IDE 的 node safe-delete 钩子拦截**：.next 里有 build 产物且文件数
   超过批量删除阈值（500）时，fs.rmSync 要求人工确认而抛错，dev server 卡在 Starting 不监听。
   绕过：先手动 Remove-Item .next（PowerShell 不受该钩子限制）再启动 dev。
   触发条件 = dev 重启前跑过 npm run build。
5. **单文件 tsc 编译与项目 tsconfig 行为不同**：jszip 的 (await import("jszip")).default
   在缺 esModuleInterop 的单文件编译下报类型错，但项目 validate 全绿——判断真实错误要跑
   npm run validate，不要被单文件编译的噪音带偏。
