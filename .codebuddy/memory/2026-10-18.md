### 2. 方案决策（用户逐项确认，4 轮）

- 压缩路线：**ffmpeg.wasm 单一方案**（放弃 WebCodecs 快路径与 WebCodecs+ffmpeg 混合，用户接受慢速换取全参数可控与全格式兼容）
- GIF 内核：**ffmpeg.wasm 一条命令出 GIF**（palettegen/paletteuse 全局调色板），不引 modern-gif/mp4box，复用压缩的 ffmpeg 单例
- wasm 核心加载：unpkg CDN + toBlobURL，二进制不入库；单线程 core 无需 COOP/COEP 头
- 参数范围：压缩 = 质量档位/分辨率/输出格式/倍速/preset（+音频固定保留不进 UI）；GIF = 起止/帧率/宽度/颜色数/循环/倍速（+抖动固定 bayer）
- 截取功能：**并入「视频压缩」工具**（一次 ffmpeg 调用同时截取+压缩），不做独立截取工具、不做 -c copy 无损模式
- 元信息文案与 changelog 1.10.0 + package.json version 同步，均已给用户过目确认

### 补充（2026-10-20，用户反馈 GIF 进度体验）

- 用户反馈：GIF 转换进度卡 0% 很久 → 0→100% 很快 → 卡 100% 很久才出下载按钮
- 根因：`palettegen` 需统计完整段视频才产出调色板，此前 `paletteuse` 零输出；ffmpeg 进度按输出时间戳计算 → 统计期恒 0%。100% 后的停留是 exec 收尾（写文件尾/关文件）+ `readFile` 读回数 MB GIF
- 用户选定方案：**分阶段进度提示**（不改引擎，零画质代价）；未选流式单趟滤镜（stats_mode=single + new=1）
- 实现：`types/video.ts` 新增 `VideoConvertPhase`（analyzing/encoding/writing）；`ffmpeg.ts` 的 `runConversion` 首个非零 progress 事件起报 encoding、exec 完成后 readFile 前报 writing；GIF 页面 analyzing 期显示不确定进度条（animate-pulse）+「全局调色板需要先统计完整段视频」说明
- 注意：compress 页面的 `onProgress` 只接 ratio 参数（TS 少参函数可赋值），未接阶段——用户未要求，保持不动
