## 教训：不要把单机结论写进随仓库同步的 memory（用户指出并纠偏）
- 起因：整理 MEMORY.md 时，我把「本机仓库路径 `e:\AI work\...`」直接写进正文，并据「本机 `d:\AI agent\...` 不存在」断言旧记录「已不存在」；同时把 SSH key 的 `C:\Users\hao\...` 直接改写成 `C:\Users\hjx\...`。
- **为什么错**：`.codebuddy/memory/` 是入库目录，会随 `git pull` 同步到用户的多台电脑（用户已确认会在不同电脑拉代码开发）。只在当前机器成立的盘符、用户名、绝对路径，到了别的机器就是错的；更严重的是**覆盖掉了另一台机器（用户名 `hao`）仍然有效的记录**，属于信息丢失。当时的推理漏洞是：只在当前机器上验证 `d:\` 不存在，就把它当成普适事实写下来。
- **后续规则（用户选方案 A，已写入 MEMORY.md 环境小节）**：
  1. memory 正文只写普适规则与探测方法——仓库路径用 `git rev-parse --show-toplevel`，SSH key 用 `$env:USERPROFILE\.ssh\id_ed25519`，Node 用 `where.exe node` 探测，**不写死盘符与用户名**。
  2. 机器特定值统一记入「各机器已确认值」表，**新增机器追加一行，禁止覆盖他行**；用 `whoami` 判断当前机器。
- 同类自我检查：以后凡是要在 memory 里写「本机 / 已核实 / 已不存在」这类结论时，先自问该结论是否只对当前机器成立。
