# 进制与浮点转换（设计）

日期：2026-11-22
状态：已实现（2026-11-22），待浏览器人工走查
入口：`/tools/design/hex-convert/`

## 目标

给程序员用的单值数值格式转换面板：输入一个值，同时看到它的十进制 / 十六进制 / 八进制 / 二进制 / IEEE754 浮点分解 / 字节串表示，并可在位网格上直接翻转某一位。

| 项 | 取值 |
| --- | --- |
| 输入 | 单个文本值（可带 `0x` / `0b` / `0o` 前缀、下划线、空格分隔） |
| 类型 | `u8 u16 u32 u64` / `s8 s16 s32 s64` / `float32 float64`，默认 `u32` |
| 输出 | 进制一览 + 位网格 + float 位域分解 + 字节串 |
| 处理位置 | 纯前端计算，无文件、无上传、无网络请求 |

## 已确认决策（2026-11-22）

| # | 决策 | 选择 | 被否方案与理由 |
| --- | --- | --- | --- |
| 1 | 工具边界 | **一个页面全能面板**（进制 + 浮点 + 位网格同页） | 拆「进制转换」+「IEEE754 分解」两页：入口选择成本转移给用户，输入解析要维护两套 |
| 2 | 批量 | **不做**，只支持单值 | 多行 → 表格输出：约 +200 行 UI 与解析容错，且批量下位网格 / float 分解无法逐个展示，等于维护第二套展示逻辑 |
| 3 | 分类 | **设计/计算区** `/tools/design/hex-convert/` | 文件工具区：该区名为「文档与文件工具」，语义不贴；新增「开发工具」分类：首页 section + Header 导航 + `ToolCategory` 类型都要动，本次改动面过大 |
| 4 | 附加视角 | **只保留位网格**；砍掉 C 数组导出、可打印 ASCII、Unix 时间戳解释 | 三项都是「顺手加」而非用户实际会用到的功能；位网格不同——它让用户能从位级别看清 float 结构，是理解 IEEE754 的关键交互 |

## 页面结构

`src/app/tools/design/hex-convert/page.tsx`（client component）：

```
输入区
  [ 值输入框 ]  [ 进制：自动 / 16 / 10 / 8 / 2 ]  [ 类型：u32 ▾ ]  [ 字节序：大端（默认）/ 小端 ]
  （错误提示行，占位不撑高页面）

进制一览
  十进制   1065353216            [复制]
  十六进制 0x3F800000  3F800000  [复制]
  八进制   0o       …            [复制]
  二进制   0011 1111 1000 …      [复制]
  （float 类型时隐藏八进制行）

位网格
  31 30 29 … 0  ← 按 8 位一组、组间留空隙；小数端与大端显示顺序相同（MSB 在左）
  点击某位 → 翻转该位 → 所有结果同步刷新

float 专属（仅 float32 / float64）
  符号 s / 指数 e / 尾数 m 三段着色
  位宽：1 / 8 / 23（float32），1 / 11 / 52（float64）
  实际指数 = e − bias，bias = 127 / 1023
  特殊值：NaN / +Inf / −Inf / denormal 明确标注
  精度提示：输入十进制与二进制实际存储值不一致时给出「实际存储 = …」

字节串
  大端：3F 80 00 00
  小端：00 00 80 3F
```

不做 Tab 切换、不做折叠：一屏看全，避免用户点开才看到自己要看的那一行。

## 解析与计算规则

新增 `src/lib/convert/numberFormat.ts`（纯函数，无 React 依赖）：

```ts
type NumType = "u8" | "u16" | "u32" | "u64" | "s8" | "s16" | "s32" | "s64" | "f32" | "f64";

parseInput(text, { radix, type, endianness }): { value: bigint | number } | { error: string }
formatAll(value, type, endianness): { dec, hex, oct, bin, bytesBE, bytesLE }
decodeFloat(bits: bigint, type): { sign, exponent, mantissa, actualExponent, kind, storedValue }
toggleBit(bits: bigint, index: number, type): bigint
```

### 输入解析

1. **预处理**：`trim` → 去掉所有 `_` 与空格（`3F 80 00 00` 等高亮粘贴习惯）。
2. **进制判定**：手动选择了进制就用它；「自动」时按前缀 `0x→16`、`0b→2`、`0o→8`，无前缀时——含 `A-F` 判 16，否则判 10。
3. **float 类型的十进制输入**：`radix === 10` 且含 `.` / `e` 时按十进制浮点读；float32 用 `Math.fround` 得到实际可表示的最近值，再从该值取位模式。
4. **多字节十六进制输入**：只有「空格分隔的两字符一组」字节串按所选**字节序**组装，默认**大端**（首字节是高位，与人书写顺序一致）；切成小端时首字节变低位，粘 `00 00 80 3F` 才得到 `1.0`。这是字节序开关存在的唯一理由，其余输入形态下该开关置灰。
5. **符号**：`s*` 接受前导 `-`，按该宽度的补码表示；`u*` 输入负数**报错**并提示「u32 不接受负数，可切换 s32」。不做静默回绕——回绕会让 `-1` 显示成 4294967295 而用户以为是位宽错。
6. **溢出**：值超出位宽上限（如 `0x1FF` 进 u8）**报错**，并提示最小可容纳类型（`0x1FF` → 建议 u16）。不做截断。

### 位网格

- 位按 `MSB → LSB` 排列，8 位一组，组间留空隙；float 类型按 `1 / 8 / 23`（或 `1 / 11 / 52`）额外画出位域分界。
- 点击翻转：`bits ^= 1n << BigInt(index)`，再按当前类型重新解释。对 `s*` 类型，翻转符号位就是翻正负；对 float，翻转指数位就能直观看到数值量级跳变——这两点正是保留位网格的价值所在。
- 位网格永远以**位模式**为准，不受字节序开关影响（字节序只影响字节串行序与多字节 hex 输入的组装方式），避免同一格子在两个开关下含义漂移。

## 错误处理

单一错误槽，就地显示在输入框下方，不清空已输入内容：

| 情况 | 提示 |
| --- | --- |
| 非法字符（该进制下） | `含非法字符 "G"，十六进制只允许 0-9 A-F` |
| 空输入 | 不报错，输出区显示占位，保持页面不跳 |
| 超出位宽 | `0x1FF 超出 u8 范围（最大 0xFF），可用 u16` |
| u 类型输入负数 | `u8 不接受负数，可切换 s8` |
| float 溢出 | `1e40 超出 float32 范围，已得到 +Inf`（正常显示 Inf，不阻断） |
| 字节数与类型位宽不符 | 允许（不足位补高 0），仅在 hex 输入长度 > 位宽时按溢出处理 |

## 风险与代价

| 风险 | 处理 |
| --- | --- |
| 64 位用 `Number` 会静默失真（> 2^53） | 整数路径全程 `BigInt`，只在最终格式化时转字符串；float64 走 `DataView`，不经过 `BigInt` |
| float32 十进制输入的舍入差（`0.1` → `0.10000000149011612`） | 用 `Math.fround` 取存储值，与输入文本比对，不一致时显式提示「实际存储 = …」，符合该工具「看清真相」的用途 |
| 位网格在高位宽（64 位）下可点击目标过小 | 每位固定最小宽度 20px，64 位分 8 组换行排列，不做横向滚动 |
| 位网格与字节序两个概念容易混淆 | 位网格固定 MSB 在左，并在区块标题旁写明「与字节序无关」 |
| `s*` 类型下 HEX/二进制是补码形式，用户可能误读 | HEX 行旁标注「补码表示」 |

## 验收标准

1. `0x3F800000` + `float32` → `1`，符号 0、指数 127（实际 0）、尾数全 0
2. `1065353216` + `u32` → HEX `0x3F800000`、BIN `0011 1111 1000 0000 …`、OCT 正确
3. 十进制 `0.1` + `float32` → 位模式 `0x3DCCCCCD`，并提示实际存储值
4. `00 00 80 3F` + 小端 + float32 → `1`；同一串切大端 → `4.6006e-41`（denormal 标注）
5. `0x1FF` + u8 → 溢出报错并建议 u16；`-1` + u8 → 拒绝；`-1` + s8 → `0xFF`（补码）
6. `18446744073709551615` + u64 → HEX `0xFFFFFFFFFFFFFFFF`，不出现精度失真
7. 位网格点第 31 位（u32）→ 值从 `0x3F800000` 变 `0xBF800000`，float32 下由 `1` 变 `-1`
8. 每个输出行复制按钮可用，剪贴板内容与显示一致
9. `npm run validate` 通过；dev 下 `/tools/design/hex-convert/` 返回 200；首页「设计/计算」区出现该卡片；`out/sitemap.xml` 含该路径

## 实现期决策（2026-11-22）

| # | 决策 | 理由 | 被否方案 |
| --- | --- | --- | --- |
| 1 | **非十进制输入按位模式解释，十进制输入按数值解释**（整型与浮点同一套规则） | 按初稿「有符号一律按数值」实现后，`0xFF` 选 `s8` 会判 255 溢出——但程序员预期是 -1。位模式语义下 `0xFF`→-1、`0x80`→-128、`0x1FF`+`u8` 仍报溢出并建议 u16，三条都对得上直觉 | 按数值解释 + 溢出报警：`0xFF` 这种 C 里最常见的写法直接不可用 |
| 2 | `tsconfig.json` 的 `target` 由 `ES2017` 改为 `ES2020` | BigInt 字面量（`0xFFn`）在更低 target 下通不过 `tsc`，而 64 位整数必须用 BigInt。只影响类型检查，产物由 Next/SWC 按浏览器目标编译 | 全部改成 `BigInt(1) << BigInt(n)`：约 50 处调用，纯啰嗦且更易写错 |
| 3 | 切换类型装不下原值时：按新位宽截断，并把输入框改写为该位模式的十六进制，**不报错** | 文本框与结果表格必须始终一致，否则用户看到的输入和显示的值对不上。类型切换是「重新解释」，不是「重新输入」 | 报错并保留文本：文本与结果脱节；报错并保留旧类型：点了没反应 |
| 4 | 翻转某一位后同样把输入框改写为该位模式的十六进制 | 同 3，位模式被直接编辑后文本必然过期 | 保留原文本：下次切类型会按旧文本回滚，用户会以为翻转丢了埋 |
| 5 | 八进制按位宽补零到 `ceil(位宽 / 3)` 位（u32 → 11 位） | 与十六进制、二进制保持同样的定宽表示，方便肉眼对齐位宽 | 不补零：数值短时看不出位宽 |
| 6 | 溢出建议只给**更宽**的类型 | 初版出现「9223372036854775808 超出 s64，可用 s64」的自我指涉提示 | — |
| 7 | 位网格每 8 位一组、组内 MSB 在左、位号标在格子下方；float 按符号 / 指数 / 尾数三色区分 | 64 位下 8 组换行比横向滚动好用；位号常显，57 位这种位置不用数 | 只在 `title` 里给位号：看不清、不能一眼定位 |
| 8 | 位视图加「左移 / 右移」按钮，**点击移 1 位**，移出位丢弃、空位补 0（**逻辑移位，`s*` 也不保留符号位**），移完输入框改写为十六进制 | 用户要求的交互就是「点一下移一下」。逻辑移位对无符号/有符号/浮点三种类型是同一套行为，不引入「算术右移」分支；若按算术右移，`s8` 的 `0x80 >> 1` 会得 `0xC0`，而 `u8` 得 `0x40`，同一按钮在切换类型后含义就变了 | 加移位量输入框：本次只要「点一下移一下」；算术右移：语义随类型漂移 |
| 9 | 「大端 / 小端」按钮**按输入自动使能**：只有空格分隔的十六进制字节串时可用，其余输入置灰并在标签旁注明「仅空格分隔的十六进制字节串可用」 | 用户反馈「float 模式切大小端十进制结果一样」——因为非字节串输入下字节序本来就不参与计算（见设计「解析规则 4」）。把开关的可用性直接画出来，比让用户去读规则可靠 | 常亮：用户以为切了没反应；让字节序对任意十六进制生效：`0x3F800000` 在小端下会被读成 `0x803F0000`，输入回显与输入不一致，更像 bug |
| 10 | 字节串格式收紧为「每段正好 2 位十六进制、段间空格、至少两段」 | 检出上一版的自动识别缺陷时一并收紧：`1010 1010` 这种分组二进制不该被当成 4 个字节 `10 10 10 10` | 只要含空格就按字节串：分组二进制的常见写法会被误读 |

| 11 | 字节序**默认大端**，且按钮顺序改为「大端 / 小端」 | 用户要求：与人书写字节串的顺序一致——先写的字节就是高位，所以 `00 00 80 3F` 默认应读成 `0x0000803F`。默认项排最左，选中态一眼可见 | 默认小端：符合 x86 内存布局，但与「从左往右读」的直觉相反 |

### 已修复缺陷（本轮发现）

- **自动识别判定错误（影响：字节串在「自动」模式下从未生效）**：初版 `detectRadix` 对 `00 00 80 3F` 返回十进制（含空格不满足纯数字正则），而字节串分支要求 `radix === 16`，导致只有手动把进制切成「十六进制」时字节串才走通，默认「自动」下会报「含非法字符 F，十进制只允许 0-9」。修法：`detectRadix` 增加「含空格且全为十六进制字符 → 16」的分支。此缺陷在写 `isByteStringInput` 的用例时暴露。
