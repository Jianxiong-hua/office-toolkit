# Color Checker（颜色对比度检查）— 设计文档 v2

> 状态：实施规划中 · 2026-08-15
> 关联项目：浩匣 / HaoXia Office Toolkit（纯前端 Next.js 工具站）
> 说明：v2 将工具从"单前景色 × 多背景色"升级为 **颜色库 + 多角色 + 联动计算** 模型。

## 1. 背景与目标

### 1.1 v1（已实现）
基于 WCAG 2.1 的"单文字色 × 多背景色"对比度检查，含经验学习、CVD、评级。

### 1.2 v2（本次升级，核心）
以**颜色库**为统一数据源，每个颜色可扮演多个角色（文字色 / 背景色 / 派生色），支持：
- **多文字色校核**：勾选为文字色的颜色各有 N 个 → 生成 N 组校核 chart
- **颜色联动**：派生色通过四则运算公式从源颜色计算，源变则目标变
- **颜色库导入**：按模板导入，导入前清空现有库、可先导出备份

### 1.3 保留能力（不回归）
WCAG 对比度算法、AA/AAA 评级、经验学习引擎、CVD 色觉模拟。

## 2. 颜色库数据模型

```ts
type ColorRole = "text" | "bg";

interface LibraryColor {
  id: string;
  name: string;          // 自定义名称
  rgb: [number, number, number];   // 实际生效 RGB
  // 角色（复选框）
  asText: boolean;       // 作为文字颜色
  asBg: boolean;         // 作为背景颜色（创建默认 true）
  // 链接 / 派生
  linked: boolean;       // 链接到其他颜色
  linkTargetId: string | null;     // 链接源颜色 id
  linkFormula: { r: string; g: string; b: string } | null;  // 每通道四则表达式
}

interface ColorLibrary {
  colors: LibraryColor[];
}
```

**派生色规则**：
- `linked = true` 时，`rgb` 由公式从 `linkTargetId` 源色计算得出，**不可手动编辑 RGB**
- 公式引用源色：表达式可用 `R` / `G` / `B` 表示源色三通道，支持 `+ - * /` 与括号，如 `R*0.8`、`(R+G)/2`
- 源色变化 → 派生色通过公式引擎重算，自动联动
- 若链接目标被删除/循环引用，标记为错误状态（红色提示），保留最后一次有效值

## 3. 多文字色校核（核心交互）

### 3.1 分组逻辑
```
文字色集合 T = { c ∈ colors | c.asText === true }
背景集合 B(c_i) = { c ∈ colors | c.asBg === true } ∪ { 其他文字色 T \ {c_i} }
```
- 为每个文字色 `c_i` 生成**一组校核 chart**：
  - 前景 = `c_i`
  - 背景 = `B(c_i)`（含其他文字色 + 勾选背景的颜色）
- 未勾选任何角色的颜色（`asText=false && asBg=false`）**不参与任何校核**
- 共生成 `|T|` 组校核 chart（文字色数量）

### 3.2 创建颜色默认角色
- 新建颜色时：`asBg = true`（默认勾选"作为背景"），`asText = false`
- 用户可后续勾选/取消

### 3.3 校核渲染
- 顶部提供文字色分组切换（Tab：文字色 A / 文字色 B / ...）
- 当前组显示该前景色 × 该组背景集合的结果卡片网格
- 每组独立保留经验核验反馈（feedback key 用 `fgHex|bgHex`）

## 4. 公式引擎（派生色）

### 4.1 `src/lib/color/formula.ts`
```ts
/** 解析并计算单通道表达式：以源色 R/G/B 为变量，支持 + - * / 与括号 */
function evalChannel(expr: string, srcRgb: [number,number,number]): number | null
```
- 将 `R` `G` `B` 替换为源色通道值，再安全求值
- 实现方式：**不 eval**，用递归下降解析器或受限 tokenizer（防注入），支持：
  - 数字、`R`/`G`/`B` 变量、`+ - * /`、`( )`、小数点
- 结果 clamp 到 [0,255]，非法表达式返回 null（UI 标红）

### 4.2 联动更新
- 当源颜色 rgb 变化 → 遍历所有 `linked` 颜色，若 `linkTargetId === 源`，重算
- 支持**链式联动**（A→B→C），拓扑排序或递归带 visited 防止循环

## 5. 颜色库初始与导入

### 5.1 初始 6 色（默认库）
| 名称 | HEX | asText | asBg |
|------|-----|--------|------|
| 红 | #FF0000 | 否 | 是 |
| 绿 | #00FF00 | 否 | 是 |
| 蓝 | #0000FF | 否 | 是 |
| 白 | #FFFFFF | 否 | 是 |
| 灰 | #808080 | 否 | 是 |
| 黑 | #000000 | 是 | 是 |

（用户可自由调整角色；此处默认黑作文字色示例）

### 5.2 导入模板（设计）
- **模板格式**：CSV（可用 Excel 打开编辑），UTF-8 带 BOM
- **模板表头**（清晰简单）：
  ```
  名称, R, G, B, 作为文字, 作为背景, 链接目标, 链接R, 链接G, 链接B
  ```
  - `名称`：必填
  - `R,G,B`：0-255 整数；若填写"链接目标"列则忽略（派生色）
  - `作为文字` / `作为背景`：填 `是/否`（空则默认 `否`/`是`）
  - `链接目标`：目标颜色名称（须为同一文件/库内已存在颜色）
  - `链接R/G/B`：四则表达式（如 `R*0.8`），仅派生色填写
- 提供**模板下载**按钮（预填 1-2 行示例）

### 5.3 导入流程
1. 点击"导入"
2. **询问**："导入将清空当前颜色库并替换，是否先将当前颜色库导出备份？" → [导出并导入] [直接导入] [取消]
3. 解析文件，若成功：清空现有 `colors`，写入文件数据
4. 校验错误（名称重复/RGB越界/链接指向不存在/公式非法）逐行提示
5. 导入前 **confirm 确认**，避免误操作

- 新建颜色（含 RGB/名称/角色勾选）
- 编辑/删除颜色
- 角色勾选（作为文字 / 作为背景）
- 链接配置（选择源 + 每通道公式）
- 颜色库导出（JSON / CSV）/ 导入（CSV 模板）

### 6.2 校核展示
- 多文字色分组 Tab 切换
- 每组结果卡片（预览/对比度/评级/反馈/经验预警/CVD）
- 排序、筛选（全部/有风险/待核验/已核验）

- localStorage key：`colorcheck_state_v2`（版本隔离 v1 旧数据）
